# Watchlist

Interesting projects that are not ready for the main awesome list yet. We usually move a project into `data/sections.json` once it has a clear license, enough adoption or maintenance signal, and factual metadata that can be verified without guessing.

## Candidates

- [Ratchet](https://github.com/suhui-organization/ratchet) — Apache-2.0 Go CLI that inventories the MCP servers an agent harness can reach, optionally connects to enumerate each server's tools, compiles allow / approve / deny with the literal reason behind every verdict, and emits a delivery whose sha256 manifest the recipient re-verifies in their own browser; also runs as a stdio MCP server. Watch because the repository was created in September 2026 with no stars or independent adoption, so the figures in its write-ups (16 servers, 12 unpinned, 164 tools) are author-measured on a single machine rather than independently reproduced; the capability classifier is a name/description heuristic that is wrong in both directions, and two false positives are documented rather than hidden; it is not a sandbox and does not block calls; and enumerating tools starts the configured servers, so that step is opt-in rather than part of the default read-only scan.
- [AgentLeak](https://github.com/yagobski/agentleak) — MIT Python SDK and CLI for privacy testing across captured agent traces, including tool calls, inter-agent messages, memory, and logs, with redacted reports, CI gates, and a local MCP interface. Watch because the installable toolkit has limited independent adoption (9 stars as of 2026-09-07); the related research artifact is separate, detector results can include false positives or missed leaks, and a clean scan is not a privacy guarantee. Deterministic trace checks run locally; live model runs and configured hosted uploads are optional, and bundled third-party data retains separately documented licenses.
- [SpendShield](https://github.com/felixpg13-glitch/spendshield) — MIT Python library and MCP server for deterministic ALLOW / APPROVAL / DENY decisions on proposed AI-agent spending, using budgets, transaction limits, merchant policy, and a hash-chained decision log. Watch because the repository is less than two weeks old with two stars and limited independent adoption; the MCP server relies on the host to keep approval, reset, secret, and policy-management tools away from an untrusted agent, its signed single-use grant executor is an experimental prototype outside the default authorization path, and the audit chain is neither keyed nor externally anchored.
- [UpClaw](https://github.com/okdkebm/UpClaw) — Apache-2.0 single-file Python CLI that runs active web reconnaissance and vulnerability checks, orchestrates optional external pentest tools, records evidence, and can send findings to an OpenAI-compatible model for prioritization. Watch because the repository is about two weeks old with one star, one maintainer, and nine unit tests around a roughly 200 KB script; TLS verification is disabled by default, the built-in checks send active attack payloads, and the tool should be reviewed and used only against explicitly authorized targets.
- [Strixgov](https://github.com/Strixgov/strix) — release mirror for an agent execution-control stack whose MIT `tool-gateway` can make inline allow, deny, and approval decisions and emit signed evidence for routed tool calls. Watch because the repository has no stars or independent adoption, its MCP adapter and proxy use Elastic-2.0 rather than MIT, and the hosted kernel and control plane are not published; wrappers protect only calls actually routed through them, so this is not a sandbox or complete agent boundary.
- [mcpaudit (catidegla)](https://github.com/catidegla/mcpaudit) — MIT zero-dependency scanner for MCP manifests and agent skills that combines multiple weighted signals, counter-evidence, a benign regression corpus, and SARIF output. Watch because the repository was created in September 2026 with no stars or independent adoption and overlaps another project named `mcpaudit`; its false-positive claims are project-tested, while the independent audit cited in its README evaluated other MCP scanners rather than this implementation.
- [agent-evidence-vectors](https://github.com/astrogilda/agent-evidence-vectors) — Apache-2.0 corpus of 461 conformance and adversarial vectors across eight corpora, with a Go verifier and a separately authored Rust checker for replaying evidence predicates. Watch because the repository is young with three stars and limited independent adoption, the relevant in-toto predicates remain proposals rather than accepted standard predicates, and the project documents that one earlier blind run could not be reproduced from committed artifacts.
- [PrivacyScrubber](https://github.com/moxno/privacyscrubber-mcp) — MIT local redaction engine, SDK, CLI, and MCP server for replacing PII and credentials with reversible placeholders. Watch because the repository has two stars, no releases or CI, and commercial tiers; MCP reverse-unmasking can return plaintext secrets to the caller, while optional command and file helpers can execute shell text or read and modify resolved host paths. Protection therefore depends on trusted integration, routing, and tool permissions, and the MCP server should not be presented as a zero-trust or complete pre-dispatch boundary.
- [http-detection-agent](https://github.com/ai-blueteam/http-detection-agent) — MIT Rust CLI and local MCP companion for bounded, capability-aware detection across normalized HTTP telemetry, with attributed rules, source profiles, coverage reports, and synthetic regression fixtures. Watch because the repository was created in September 2026 with no stars or independent adoption; it is primarily a deterministic HTTP detection engine with an MCP interface rather than an AI/ML detector, and its synthetic fixtures do not establish real-world precision or recall.
- [PasteGuard](https://github.com/ExtendedUser/pasteguard) — MIT single-page browser utility that heuristically finds API keys, tokens, private keys, and PII before text is pasted into an AI chat, then produces a redacted copy locally. Watch because the repository is only days old with no stars, releases, tests, CI, or independent adoption; the detector is a compact pattern-based utility rather than a guarantee that text is safe to disclose.
- [whatileaked](https://github.com/selan-ai/whatileaked) — MIT local scanner for credentials already present in supported Claude Code, Codex, and Cursor transcripts or instruction files, using the unmodified Gitleaks rule set and reporting one-way fingerprints instead of secret values. Watch because the repository is only about a week old with low single-digit adoption; regex rules retain their usual false-positive and false-negative tradeoffs, supported sources are path-specific, and the separately confirmed `wipe` command irreversibly rewrites matching files without creating a backup and cannot undo disclosure to a model provider.
- [Verb Authority](https://github.com/yairsabag/verb-authority) — Apache-2.0 Python gate and schema scanner that infers per-argument authority for selected agent tool calls and tracks limited value provenance before execution. Watch because the repository has no stars or independent adoption yet, trusted argument values and application identity are supplied by the integrator, and the library is a scoped in-process gate rather than a standalone authorization or sandbox boundary.
- [mcpbait](https://github.com/jankesec/mcpbait) — Apache-2.0 offensive red-team framework that tests MCP-speaking agents against intentionally rogue local servers, including tool poisoning, persistence, and canary-based exfiltration scenarios. Watch because the repository is only days old with no independent adoption; its server-side observations do not by themselves prove agent safety, and authorized tests can alter client configuration or decoy workspaces and should use disposable profiles rather than production environments.
- [Agent Outbound Guard](https://github.com/Kndll33/agent-outbound-guard) — MIT zero-dependency Python pre-send static linter for agent-generated email JSON that blocks malformed or duplicate recipients, missing bodies or stable idempotency keys, unresolved placeholders, likely secrets, exported line-number prefixes, and invalid field types, with machine-readable findings for CI. Watch because the repository is new with no stars or independent adoption, secret detection is intentionally conservative, and the tool does not send mail, validate deliverability, guarantee policy compliance, or provide a runtime security boundary.
- [Repo Agent Instruction Security Scan](https://github.com/sunxiayi/repo-agent-instruction-security-scan) — MIT zero-dependency Node CLI, pre-commit hook, and GitHub Action that statically screens AGENTS.md, CLAUDE.md, Cursor, Copilot, Gemini, and Windsurf instruction files for eight deterministic risk patterns, emitting text, JSON, and SARIF without executing instruction content or making scan-time network requests. Watch because the repository is new with no stars or independent adoption; pattern matching can miss malicious intent or flag legitimate maintenance instructions, and JSON/SARIF evidence may retain excerpts from sensitive instruction files and should itself be handled as sensitive output.
- [Lumi Eggcracker](https://github.com/noqt/Lumi-Eggcracker) — Apache-2.0 public-alpha Linux guard that uses pidfds and cgroup v2 to kill the complete process tree of an unapproved workload only after a full match to one of two published content profiles, then writes a bounded empty-tree receipt. Watch because the repository is new with no stars or independent field runs, the supported path requires root on disposable native Ubuntu, and it does not claim containers, remote services, network or credential isolation, behavioural detection, malware prevention, or universal AI recognition.
- [Nemesis Forge](https://github.com/eobi/nemesisforge) — MIT autonomous C/C++ vulnerability-discovery engine in which an LLM can propose fuzz harnesses and triage routes while deterministic sanitizer, replay, differential, controllability, exploitability, and symbolic oracles decide what evidence is established. Watch because it is a new single-maintainer project with minimal adoption, no CI or published release, and its local/Windows execution backends are explicitly not isolation; harness synthesis requires a configured model, and generated or third-party targets should be run only in the documented Docker sandbox on authorized code.
- [Lumi Trace](https://github.com/noqt/Lumi-Trace) — Apache-2.0 local deterministic SARIF finding-localisation and evidence CLI with a zero-dependency public runtime, extensive tests, and optional network-denied Docker reproduction. Watch because the repository is new with no independent adoption, the public package currently provides general finding-guided ranking rather than AI/LLM-specific analysis, and its documented learned ranker remains a private development candidate whose weights are not published or included in the package.
- [Awesome Agentic Engineering](https://github.com/lindixu6-hash/awesome-agentic-engineering) — MIT self-declared readiness scorecard and CI gate for AI agents, with risk profiles, eight inert prompt-injection fixtures, machine-readable results, and LangGraph.js evaluation adapters that retain node-linked tool and policy traces. Watch because it is broader agent-engineering guidance rather than a security scanner or enforcement control, the project is one day old with minimal adoption, and its CI/evaluation evidence and only listed adopter are author-operated.
- [TRACE](https://github.com/ionsec/trace) — AGPL-3.0 alpha CLI and Go binary for read-only local collection and analysis of AI/LLM forensic artifacts, including model-runner, coding-agent, browser, Docker, network, conversation, credential, timeline, and STIX evidence. Watch because the repository was created on 2026-08-14 with no stars and its large initial implementation arrived in a single commit; the broad capability claims lack independent validation, collected evidence is highly sensitive, and the security-policy version table still lags the current 1.0.1 package.
- [Agent Trust](https://github.com/Rain-ouroboros/agent-trust) — advisory receipt library for AI-agent prompts, actions, scopes, and tool descriptors. Watch because the repository is very new, has no stars yet, and the current PR wording overstates runtime enforcement and packaging status.
- [Skarn](https://github.com/skarn-security/skarn-action) — GitHub Action wrapper that scans AI coding-assistant session logs for leaked credentials and attack patterns, then emits redacted SARIF and risk output. Watch because the repository is very new and currently has no stars; the public repo is an MIT Action wrapper, while the scanner engine is a proprietary EULA binary that requires a license token.
- [Purser](https://github.com/purser-io/purser) — static security scanner for ML model artifacts across 18+ formats (pickle/PyTorch/Keras/GGUF/ONNX/safetensors) with a data-exfiltration engine, trust_remote_code AST analysis, a country-of-origin/publisher/format policy engine, signed provenance, and CI + Kubernetes admission enforcement. Watch because the repository is very new and currently has low single-digit stars; it ships a clear Apache-2.0 license, is installable (PyPI, signed GHCR images, Helm chart), and is actively maintained.
- [ARIA](https://github.com/sidevworks/aria-sec) — source-available AI security-operations cockpit with governed autonomy, AI-SPM connectors, local-model support, and audit controls. Watch because the repository is one day old with no stars, the author describes it as active solo development with demo-grade parts, and BSL-1.1 requires a commercial production license until its 2030-07-26 GPL conversion.
- [VERITAS Omega Agent Trust Lab](https://github.com/VrtxOmega/veritas-agent-trust-lab) — zero-signup browser challenge for labeling six fixed AI-agent assurance results as clean or tampered before revealing deterministic answers, covering forged verdicts, parameter substitution, nonce replay, correlated evaluators, evidence deletion, and missing telemetry. Watch because the MIT-licensed repository is new and currently has no stars, forks, or eligible external calibration submissions; its release evidence is author-operated and does not establish product efficacy.
- [gate.cat](https://github.com/BGMLAI/gate.cat) — deterministic, fail-closed deny-list that vetoes an AI coding agent's irreversible shell commands (`rm -rf`, disk wipe, prod-DB drop, secret exfiltration) before they run. Watch because the repository is very new and currently has low single-digit stars; it ships a clear Apache-2.0 license, is installable (PyPI, `pip install gate.cat`), publishes its own false-block measurement in the repo, and is actively maintained. Claude Code has a native pre-execution hook; other agents use the provided shell wrapper or integration points.
- [agentsurface](https://github.com/Northbeams-Labs/agentsurface) — local CLI that inventories the AI agent machinery installed on a machine: MCP servers across many clients, desktop extensions, plugins, skills, connectors, scheduled agent tasks, instruction files, and AI browser extensions with their native messaging hosts, reporting what each item declares it can reach. Watch because the repository is very new with minimal adoption; it ships a clear Apache-2.0 license, is installable (Homebrew tap and `go install`), makes no network calls at all (enforced by a CI check that fails the release), and states plainly that it is an inventory: no risk score, no malice judgement, and no prompt-injection detection. Signed archives cover macOS and Linux; Windows is supported through `go install`.
- [Koma](https://github.com/swnotmetal/Project-Koma) — MIT TypeScript monorepo with three npm middleware packages: LLM-based scope filtering, request/audio perimeter checks, and a split-store access pattern. Watch because the project was created in July 2026 and has limited adoption; its Gate layer defaults to fail-open and uses an LLM classifier rather than a demonstrated prompt-injection defence.
- [mcpaudit](https://github.com/AndrewXuTurtle/mcpaudit) — MIT config-side auditor for MCP servers already configured in local AI clients, checking tool poisoning, credential exposure, supply-chain provenance, and advisories without executing the subject server. Watch because the project is newly published with no independent adoption signal; it queries package/advisory registries and, with `--deep`, downloads tarballs for static inspection.
- [Ice Phi Enterprise Shield](https://github.com/Ice-Phi/icephi-python) — MIT Python client for Ice Phi's hosted prompt-security gateway. Watch because the repository is newly published with limited public implementation evidence; its protection runs through a commercial API and therefore needs a `commercial_open` / `requires_api_key` treatment if it later graduates to the main list.
- [bounty-trap-scan](https://github.com/sujeito-operator/bounty-trap-scan) — MIT, stdlib-only Python scanners over GitHub's open `💎 Bounty` issues: one classifies which issues instruct an autonomous contributor to paste its own system prompt into the file it is being paid to change, the other reads the newest 400 pull requests in each of the three largest such repositories and counts what agents actually published back; the raw scan, compliance and attribution JSONs are committed beside the code and each script has a no-network `--selftest`. Watch because the repository was created 2026-08-08, has no stars, and is single-author; today its value is the committed dataset and a reproducible one-line GitHub search rather than adoption or independent verification, and its README carries three dated self-corrections — including one withdrawing a bounty-platform attribution the scanner had never measured.
- [SovereignRoot](https://github.com/BryanFiFife/SovereignRoot) — Apache-2.0 working protocol and local-first browser generator for a cryptographically signed `sovereignty.json`: a human-owned root constraint policy (deny-overrides, attenuation-only) that caps delegated AI-agent authority. Watch because the repository is brand new with no stars yet; it ships a clear Apache-2.0 license, a tagged v0.1.1 release with checksum, a dependency-free static site, and a reference verifier/policy engine, but needs independent adoption and maintenance signal before graduating to the main list.
- [CrewScore](https://github.com/shmindmaster/crewscore) — MIT offline deterministic linter for missing written safeguards in agent system prompts and coding-agent configuration, with 23 public controls, a CLI, GitHub Action, browser checker, and SARIF output. Watch because the repository is only a few weeks old with one star; its corpus study and construct-validity evidence are unusually transparent but author-operated, and written-control coverage is not runtime-security proof.
- [PolicyStrata](https://github.com/raintree-technology/policystrata) — MIT deterministic CI regression tester for policy drift across model-visible tool manifests, semantic validation, SQL compilation, database containment, and result release in data-agent stacks; emits minimized witnesses and SARIF. Watch because the narrowly scoped project is less than two months old with one star; its reproducible fault-model results are useful regression evidence, not independent production-recall or authorization proof.
- [Aegis Memory](https://github.com/quantifylabs/aegis-memory) — Apache-2.0 secure memory/context layer with an offline write gate, unsafe-memory-flow inspection, self-hosted storage, and project-published prompt-injection benchmarks. Watch because adoption is still limited, its benchmark evidence is project-operated, and the main list already includes OWASP Agent Memory Guard in the same emerging niche.
- [Agent Security Scanner MCP](https://github.com/sinewaveai/agent-security-scanner-mcp) — MIT MCP server combining project, dependency, package-hallucination, prompt, MCP, and AST/taint scans for coding agents. Watch because the scanner makes unusually broad feature and corpus-size claims for a young project in an already crowded category; the claimed coverage needs focused static and benchmark verification before promotion.
- [agent-approval-gate](https://github.com/Prime-agentai/agent-approval-gate) — MIT `PreToolUse` hooks that queue approval for spending, account, fund-movement, secret-bearing command, token-budget, and repeat-loop actions. Watch because the project is new with minimal independent adoption, has no GitHub CI, and is maintained by an autonomous AI agent under disclosed human approval; its probe reports improve visibility but do not prove that every host or subagent invokes the hooks.
- [MARGINAL](https://github.com/SignalLayerLabs/Marginal) — Apache-2.0 local-first governor that records evidence of repeated successful coding-agent actions with unchanged state and can earn narrow Codex enforcement after shadow-mode observation. Watch because the project is young and currently addresses availability and compute-governance risk more directly than adversarial security; Claude Code and OpenCode are observe-only, failures fail open, and the published three-task smoke resolved no tasks and applied no denies.
- [SecureAI-Scan](https://github.com/akanthed/SecureAI-Scan) — MIT offline static scanner for TypeScript, JavaScript, Python, MCP configurations, agent skills, and RAG code, using import-resolved AST/dataflow evidence and producing SARIF. Watch because adoption remains limited and its precision and regression results are maintainer-operated; the project correctly notes that static scanning is a filter, not a security boundary.
- [Patronus Ark](https://github.com/patronus-protect/patronus-security) — GPL-3.0-only or commercially licensed Rust/Python library that scans prompts, tool traffic, and documents locally for injection, DLP, PII, and agentic tool risks. Watch because adoption is still low, its benchmark uses bundled validation samples, and higher-level ONNX assets require an initial Hugging Face sync and may require `HF_TOKEN` before offline operation.
- [Lazaretto](https://github.com/jamesdfinance-dev/lazaretto-mcp) — MIT MCP client for a hosted proprietary package, lockfile, artifact, and agent-skill verification service with signed verdicts. Watch because the public repository contains no detection engine or tests, lockfile and artifact contents leave the machine for analysis, and the paid scanner cannot be independently validated from the client source.
- [Clay Seal Identity](https://github.com/clayseal/clayseal-identity) and [Receipts](https://github.com/clayseal/clayseal-receipts) — MIT libraries for short-lived attested workload credentials, optional MCP authorization, and signed offline-verifiable action receipts. Watch because the two repositories are new with limited adoption; Identity establishes who is acting but does not inspect prompt injection, while Receipts is an audit/proof layer rather than a sandbox or standalone authorization boundary.
- [Sentinel Scan](https://github.com/Ventrova/sentinel-scan-cli) — MIT CLI for authorized prompt-injection, jailbreak, and data-leak smoke tests against LLM applications. Watch because the project is only days old with no adoption signal, its current suite contains 15 stock probes with heuristic secret/refusal scoring, and published packages lag the repository's advertised feature set.
- [attenu-guard](https://github.com/attenu-io/attenu-guard) — Apache-2.0 Python library (PyPI `attenu-guard`) that enforces caller-declared per-agent permissions in-process on tool calls and sub-agent handoffs, computing each sub-agent's authority as a subset of its parent's, and writes a hash-chained audit log with optional signed anchors plus Ed25519-signed delegation tokens for offline verification; adapters cover LangGraph, CrewAI, Google ADK, OpenAI Agents SDK, Claude Agent SDK, MCP and others. Watch because the repository went public in August 2026 with minimal independent adoption; it is an enforcement shim rather than a sandbox, authority remains the integrator's responsibility, Ed25519 requires the optional cryptography dependency, and published adversarial results are maintainer-operated.
- [Provael](https://github.com/provael/provael) — Apache-2.0 CPU-first red-team harness for vision-language-action robot policies: it perturbs the instruction and camera observation a policy receives inside a simulator and reports an attack success rate with a 95% Wilson interval beside a matched benign-control false-positive floor, emitting SARIF, OSCAL, a CycloneDX ML-BOM and an Ed25519-signed leaderboard row. Watch because the repository is two months old with low single-digit stars and has measured exactly one policy on one suite; it ships a clear Apache-2.0 license, is installable (PyPI, `pip install provael`), and publishes its own null results — two of the three measured attack families scored 0% against the real model — beside the positive one. Simulation only: nothing here has run on a physical robot, and the repository states that rather than implying transfer.
- [ci-prompt-shield](https://github.com/Rezarys/ci-prompt-shield) — MIT GitHub Action that removes selected hidden encodings and HTML concealment from issue, pull-request, or comment text before a CI coding agent consumes it, while flagging several natural-language prompt-injection patterns. Watch because the repository is new with no independent adoption; ordinary injection phrases are reported but intentionally remain in `clean_text`, regex-based HTML handling is not a complete parser, and consumers must enforce a separate block or review decision rather than treat sanitized output as trusted.
- [browser-bridge](https://github.com/1clawAI/browser-bridge) — Apache-2.0 CDP credential-fill gateway for AI agents: the agent drives Chromium normally, while the bridge types logins and reads site-issued API keys in a separate target the agent does not script; local-file, in-memory, and hosted vault backends are available. Watch because the repository is new with a single star and no independent adoption; the isolation claim requires the bridge to be the only browser/CDP connection and host bindings to come from a trusted human, while the hosted backend sends policy and fill metadata to 1Claw and the guarantee covers only the bridge's credential-fill path.
- [memory-blackbox](https://github.com/lavkumarv/memory-blackbox) — Apache-2.0 Python toolkit that records AI-agent memory reads and writes routed through its adapters, instruction-file differ, MCP gateway, or sidecar into an append-only ledger (BLAKE3 hash chain, Ed25519 signatures, signed Merkle checkpoints) and a provenance DAG, then traces a harmful action to the memory that caused it, computes the forward closure of a poisoned source, and quarantines it by appending rather than deleting. Watch because the repository was created 2026-06-30, currently has a single star and one public release, and its detector pack, semantic-drift scoring, and OWASP/ATLAS/CoSAI mappings are author-asserted without independent validation; it is explicitly post-incident reconstruction and enforces nothing at runtime, capture is only as complete as the paths routed through it, and the resulting ledger is itself a sensitive record of agent memory.
