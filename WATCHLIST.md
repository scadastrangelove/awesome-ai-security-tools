# Watchlist

Interesting projects that are not ready for the main awesome list yet. We usually move a project into `data/sections.json` once it has a clear license, enough adoption or maintenance signal, and factual metadata that can be verified without guessing.

## Candidates

- [jevc](https://github.com/doronp/jevc) — Apache-2.0 TypeScript compiler that lowers repository agent instructions into typed evidence questions plus a deterministic first-match verdict reducer, with emitters for several agent frameworks and policy formats. Watch because the repository was created in September 2026 with four stars and no independent adoption; generated bouncer policy deliberately defaults to `mode: observe` and `on_error: passthrough`, so it is an authoring and calibration tool rather than an enforcement boundary. Most operation is offline, while the optional live check calls TypeSafe's commercial Jev API; the project's own recorded evaluation found that only 23 of 58 predicted thresholds survived live-model testing.
- [rule-audit](https://github.com/hermes-labs-ai/rule-audit) — MIT deterministic CLI and library for finding ambiguity, contradictions, missing conditions, unreachable rules, and other structural weaknesses in agent prompts and policy text. Watch because the project has three stars and limited independent adoption; its analysis is a useful heuristic linter built around parsing and linguistic patterns, not a formal logic solver, runtime enforcement layer, or proof that an agent will obey the reviewed instructions.
- [claude-security-audit](https://github.com/TobiasVeiga00/claude-security-audit) — MIT Claude Code plugin and skill bundle for authorized application-security review, scanner-result ingestion, finding validation, prioritization, and report generation. Watch because the repository was created in September 2026 with one star and review quality depends substantially on the host model; its authorization hook fails closed only for commands matching its intrusive-tool patterns, while ordinary commands can pass when evaluation fails, so it is an agent workflow rather than a complete execution boundary. Use only on explicitly authorized targets.
- [is-malicious](https://github.com/luantak/is-malicious) — MIT Node.js CLI and agent skill that sends selected repository files to TypeSafe Jev for model-based review of covert behaviour, data theft, hidden execution, persistence, and supply-chain manipulation before the target is run. Watch because the young project has limited independent adoption; scans require a paid third-party API key and upload selected source and configuration content, unsupported or large files are skipped, model results can be wrong in either direction, and the tool neither sandboxes code nor makes a clean result a safety guarantee.
- [Ratchet](https://github.com/suhui-organization/ratchet) — Apache-2.0 Go CLI and MCP server that inventories configured MCP servers, optionally enumerates their tools, and compiles reasoned allow, approve, or deny policy artifacts with a verifiable delivery manifest. Watch because the repository was created in September 2026 with no stars or independent adoption; capability classification is heuristic, the tool does not enforce or sandbox calls, and its optional introspection mode starts the configured MCP servers rather than performing a purely static scan.
- [ThreatCluster MCP](https://github.com/Jam0k/Threat-Intelligence-MCP) — GPL-3.0 Python and Node MCP clients that expose read-only threat-intelligence lookups from the commercial ThreatCluster service. Watch because the repository is new with one star and contains thin wrappers rather than the detection or intelligence engine; useful operation requires a ThreatCluster API key and consumes the hosted service's free or paid credits, so results cannot be independently reproduced from the public client alone.
- [agentgate (ciceroyang)](https://github.com/ciceroyang/agentgate) — AGPL-3.0 zero-runtime-dependency control plane that inventories agent tooling, records scanner coverage, applies policy checks, and emits evidence and SARIF without reporting a clean verdict when required measurements are absent. Watch because the project was created in September 2026 with one star, published validation is maintainer-operated, a commercial license is offered for closed-source service use, and its name overlaps several unrelated AgentGate projects.
- [shim-cli](https://github.com/GetSHIM/shim-cli) — Apache-2.0 local hooks and an opt-in loopback traffic observer for coding agents, with deterministic secret and personal-data detection and eligible Claude Code tool-result masking. Watch because the repository is less than a month old with seven stars, no forks, two contributors, and little independent adoption; user prompts are report-only by default, prompt-injection markers are flagged rather than neutralized, verified tool-result masking is limited to Claude Code, and `shim watch` currently supports Claude Code only. Treat it as a best-effort privacy control, not a data-loss-prevention boundary.
- [mcp-nameguard](https://github.com/sushant-me/mcp-nameguard) — MIT zero-dependency Python CLI that compares MCP tool names with names reserved by supported agent frameworks and can fail CI on collisions. Watch because the repository was created in September 2026 with no stars; coverage currently focuses on the ADK family, names are checked without analysing tool descriptions or prompt injection, and live modes are not purely static: stdio mode starts the configured candidate server while HTTP mode connects to it with supplied authentication headers.
- [prompt-protection](https://github.com/mughalhere/prompt-protection) — MIT zero-dependency TypeScript library that labels untrusted tool data and applies caller-supplied source, destination, and sink policy before selected agent tool calls. Watch because the project has three stars and limited independent adoption; protection is a cooperative in-process wrapper rather than a sandbox, provider-executed tools without an `execute` function are skipped, trust and sink mappings remain the integrator's responsibility, and the published benchmark is maintainer-operated with a reported 19.4% false-positive rate on its hard-negative set.
- [SecHelix](https://github.com/omarmohelal/SecHelix) — Apache-2.0 agent skill with an optional Python runner and read-only MCP adapter for evidence-oriented application-security review of authorized repositories, including specialist review lanes and a separate finding-refutation pass. Watch because the repository is young with one star and a single maintainer; full-workflow detection performance is explicitly not measured, the published blind-label result covers a narrower task, and review quality still depends on the host model's reasoning.
- [pod](https://github.com/suhui-organization/pod) — Apache-2.0 TypeScript CLI and MCP gateway that records agent tool use, compiles observed permissions into a least-privilege policy, enforces deny, approve, and allow decisions on routed calls, and appends calls to a SHA-256 hash chain. Watch because the September 2026 repository has one star and no independent adoption; enforcement covers only calls routed through the gateway, the baseline policy is a starting template, record mode intentionally passes calls, and the hash chain establishes internal consistency rather than an externally anchored or keyed attestation.
- [agent-canary](https://github.com/DorianChn/shanchuanzhi-agent-canary) — MIT canary system that exposes inert decoy tools and planted tokens to make suspicious agent interaction observable through local traces and alerts. Watch because the project was created in September 2026 and its zero-false-positive and effectiveness claims are maintainer-operated; it detects interaction with configured decoys but does not contain unrelated actions, coverage depends on routing agents through its integrations, and optional evaluation, dashboard, and export features are commercial.
- [agent-gate (DorianChn)](https://github.com/DorianChn/agent-gate) — Apache-2.0 Python policy gateway for selected AI-agent and MCP tool calls with parameter rules, short-lived credentials, audit logging, and proxy integrations. Watch because the project is young with one star and limited independent adoption; its MCP proxy launches the configured server command through a shell, so configuration must be trusted, and only calls routed through the gateway are governed.
- [traceplay](https://github.com/DorianChn/traceplay) — MIT deterministic recorder and replayer for agent and LLM interactions, with tool-call assertions, forbidden-tool checks, and CI-oriented replay. Watch because the young project has one star and is a general testing harness rather than a security boundary; recorded cassettes can contain raw LLM request and response bodies, making the generated artifacts potentially sensitive and unsuitable for unreviewed publication.
- [RepoSieve](https://github.com/DorianChn/reposieve) — MIT local repository context packer for coding agents with generated-file filtering, token budgets, and secret-like value redaction. Watch because the project was created in September 2026 with one star; its compact pattern-based redaction is best effort and can miss sensitive values, so a generated context bundle must still be reviewed before it is sent to a model provider.
- [AgentLeak](https://github.com/yagobski/agentleak) — MIT Python SDK and CLI for privacy testing across captured agent traces, including tool calls, inter-agent messages, memory, and logs, with redacted reports, CI gates, and a local MCP interface. Watch because the installable toolkit has limited independent adoption (9 stars as of 2026-09-07); the related research artifact is separate, detector results can include false positives or missed leaks, and a clean scan is not a privacy guarantee. Deterministic trace checks run locally; live model runs and configured hosted uploads are optional, and bundled third-party data retains separately documented licenses.
- [SpendShield](https://github.com/felixpg13-glitch/spendshield) — MIT Python library and MCP server for deterministic ALLOW / APPROVAL / DENY decisions on proposed AI-agent spending, using budgets, transaction limits, merchant policy, and a hash-chained decision log. Watch because the repository is less than two weeks old with two stars and limited independent adoption; the MCP server relies on the host to keep approval, reset, secret, and policy-management tools away from an untrusted agent, its signed single-use grant executor is an experimental prototype outside the default authorization path, and the audit chain is neither keyed nor externally anchored.
- [UpClaw](https://github.com/okdkebm/UpClaw) — Apache-2.0 single-file Python CLI that runs active web reconnaissance and vulnerability checks, orchestrates optional external pentest tools, records evidence, and can send findings to an OpenAI-compatible model for prioritization. Watch because the repository is about two weeks old with one star, one maintainer, and nine unit tests around a roughly 200 KB script; TLS verification is disabled by default, the built-in checks send active attack payloads, and the tool should be reviewed and used only against explicitly authorized targets.
- [Strixgov](https://github.com/Strixgov/strix) — release mirror for an agent execution-control stack whose MIT `tool-gateway` can make inline allow, deny, and approval decisions and emit signed evidence for routed tool calls. Watch because the repository has no stars or independent adoption, its MCP adapter and proxy use Elastic-2.0 rather than MIT, and the hosted kernel and control plane are not published; wrappers protect only calls actually routed through them, so this is not a sandbox or complete agent boundary.
- [mcpaudit (catidegla)](https://github.com/catidegla/mcpaudit) — MIT zero-dependency scanner for MCP manifests and agent skills that combines multiple weighted signals, counter-evidence, a benign regression corpus, and SARIF output. Watch because the repository was created in September 2026 with no stars or independent adoption and overlaps another project named `mcpaudit`; its false-positive claims are project-tested, while the independent audit cited in its README evaluated other MCP scanners rather than this implementation.
- [agent-evidence-vectors](https://github.com/astrogilda/agent-evidence-vectors) — Apache-2.0 corpus of 461 conformance and adversarial vectors across eight corpora, with a Go verifier and a separately authored Rust checker for replaying evidence predicates. Watch because the repository is young with three stars and limited independent adoption, the relevant in-toto predicates remain proposals rather than accepted standard predicates, and the project documents that one earlier blind run could not be reproduced from committed artifacts.
- [PrivacyScrubber](https://github.com/moxno/privacyscrubber-mcp) — MIT local redaction engine, SDK, CLI, and MCP server for replacing PII and credentials with reversible placeholders. Watch because the repository has two stars, no releases or CI, and commercial tiers; MCP reverse-unmasking can return plaintext secrets to the caller, while optional command and file helpers can execute shell text or read and modify resolved host paths. Protection therefore depends on trusted integration, routing, and tool permissions, and the MCP server should not be presented as a zero-trust or complete pre-dispatch boundary.
- [http-detection-agent](https://github.com/ai-blueteam/http-detection-agent) — MIT Rust CLI and local MCP companion for bounded, capability-aware detection across normalized HTTP telemetry, with attributed rules, source profiles, coverage reports, and synthetic regression fixtures. Watch because the repository was created in September 2026 with no stars or independent adoption; it is primarily a deterministic HTTP detection engine with an MCP interface rather than an AI/ML detector, and its synthetic fixtures do not establish real-world precision or recall.
- [PasteGuard](https://github.com/ExtendedUser/pasteguard) — MIT single-page browser utility that heuristically finds API keys, tokens, private keys, and PII before text is pasted into an AI chat, then produces a redacted copy locally. Watch because the repository is only days old with no stars, releases, tests, CI, or independent adoption; the detector is a compact pattern-based utility rather than a guarantee that text is safe to disclose.

Watch because the repository is only about a week old with low single-digit adoption; regex rules retain their usual false-positive and false-negative tradeoffs, supported sources are path-specific, and the separately confirmed `wipe` command irreversibly rewrites matching files without creating a backup and cannot undo disclosure to a model provider.
